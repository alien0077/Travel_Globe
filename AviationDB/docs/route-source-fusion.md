# Route Source Fusion

This pack separates route existence from route geometry provenance.

## Source Tiers

1. `observed_adsb`
   - ADS-B trace-derived route shape.
   - Highest confidence for replay geometry.
   - Private offline pack only.

2. `recovered_endpoint`
   - ADS-B trace-derived route shape whose endpoint was recovered by route context.
   - Used only when endpoint direction, distance, route progress, and nearby-airport competition are all reasonable.
   - Must retain recovery metadata for audit.

3. `static_route_graph`
   - Historical airport-pair graph from the local aviation context pack.
   - Useful for route existence and fallback pairing.
   - Lower confidence than observed tracks; not a precise flown path.

4. `airport_pair_fallback`
   - Generated fallback shape when an airport pair exists but no observed ADS-B route is available.
   - Should render as an estimated route, not as an observed flight path.

5. `adsbdb_targeted`
   - Callsign/flightroute lookup candidate only.
   - Do not bulk-copy route data into local databases without permission.

6. `airportroutes_targeted`
   - Airport-pair lookup candidate only.
   - Route data should be treated as external/manual-review input until redistribution terms are clarified.

## KHH Finding

The 21-day observed pack has no `KHH` endpoint routes, but the static route graph shows active KHH pairs such as `KHH-NRT` and `KHH-HKG`.

That means the fix should not be KHH-only. The builder needs global endpoint recovery diagnostics for airports where static route activity is high but observed endpoint samples are zero or near-zero.
